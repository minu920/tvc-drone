# 5단계 — 연구기체 기준 사양 v0와 전체 과정

작성: 2026-09-16. 이 사양은 보유 장비를 판정하고 첫 벤치를 만들기 위한 시작점이다.
특정 모터·프로펠러 조합의 비행 성능을 보증하지 않으며, 계측 결과에 따라 변경한다.

## 결론

다음 기준으로 시작한다.

- 최대 이륙질량 목표: **1.3–1.8 kg**, 설계 상한 1.8 kg.
- 전원: **6S LiPo 계열**.
- 추진: **8–9인치 프로펠러를 사용하는 독립 모터 2개의 동축 반전 구조**.
- 추력 방향: 2축 TVC, 기계적 동작 범위 ±15° 이상, 초기 제어 명령은 ±8°로 제한.
- 실시간 제어: **PX4가 지원되는 Pixhawk FMUv6X급 비행제어기** 또는 동급 H7 보드.
- 고수준 연산: Jetson Orin Nano. VIO·영상·ROS 2·실험 기록 담당.
- 첫 실물 목표: 프로펠러 없는 TVC 벤치. Jetson은 초기에는 기체 밖에서 전원 어댑터로 사용.
- 첫 비행 목표: 센서 융합이나 MPC가 아닌, 비행제어기 단독 자세 안정화와 안전 종료 검증.

원본 약 0.4 kg 기체에 Jetson 개발키트와 대형 센서를 단순 추가하지 않는다. 탑재 후 질량과 관성이 달라지므로 추진계와 프레임을 새로 검증한다.
원본의 84 mm급 3MF를 균일 확대해서 사용하지도 않는다. 새 부품 치수와 질량을 기준으로 하중 골격, TVC 짐벌, 트레이와 분할 외피를 파라메트릭 CAD로 재설계한다.
세부 기준은 [확대 사양용 기체 CAD 재설계 계획](CAD-재설계-계획.md)에 정리했다.

## 1. 추력 요구조건

설계 상한 질량을 다음과 같이 둔다.

\[
m_{\max}=1.8\ \mathrm{kg}
\]

무게는 다음과 같다.

\[
W_{\max}=m_{\max}g=1.8\times9.81\approx17.7\ \mathrm{N}
\]

배터리 저전압에서 보호 지그로 측정한 동축 조립체의 최대 총추력 목표는 무게의 2배로 둔다.

\[
T_{\max}\cos 15^\circ \ge 2W_{\max}
\]

따라서 추력축 기준 목표는 다음과 같다.

\[
T_{\max}\ge\frac{2\times17.7}{\cos15^\circ}\approx36.6\ \mathrm{N}
\]

즉, **6S 배터리의 최저 운용 전압에서 동축 조립체 실측 총추력 37 N 이상**을 1차 목표로 둔다.
이는 약 3.73 kgf에 해당한다. 추력/무게 비율 2는 이 연구기체의 설계 목표이지 모든 TVC 기체의 보편적 안전 기준이 아니다.

동축 손실을 처음에는 25%로 가정하면, 모터 하나의 단독 추력표는 동일한 전압·프로펠러에서 최소 다음 정도가 필요하다.

\[
T_{\mathrm{single}}\ge\frac{36.6}{2\times0.75}\approx24.4\ \mathrm{N}
\]

따라서 보유 모터·프로펠러 조합은 **모터 하나당 단독 정지추력 약 25 N 이상**을 후보 기준으로 확인한다.
25%는 선택을 위한 보수적 초기 가정일 뿐이다. 최종값은 상·하 로터 간격과 회전 방향을 포함한 동축 실측으로 교체한다.

## 2. 모터와 프로펠러 사양

### 시작 후보 범위

| 항목 | 기준 사양 v0 |
|---|---|
| 모터 수 | 동일 계열 2개, 각 모터를 독립 제어 |
| 배터리 | 6S 대응 |
| 프로펠러 | 8–9인치, 동일 형상의 CW/CCW 한 쌍 |
| 모터 크기 후보 | 대략 2808–3110급 외전형. 숫자만으로 적합성을 판정하지 않음 |
| KV 후보 | 대략 700–1000 KV. 최종 선택은 제조사 추력표와 실측으로 결정 |
| 단독 추력 목표 | 모터당 약 25 N 이상, 최저 운용 전압 기준 |
| 연속 운전 | 목표 호버 추력에서 과열 없이 반복 운전 가능해야 함 |
| 데이터 | 전압, 프로펠러, 추력, 전류, 입력, RPM, 온도 조건이 있는 시험표 필요 |

KV·모터 크기·프로펠러 직경 중 하나만으로 선택하지 않는다. 같은 KV라도 권선, 자석, 냉각, 프로펠러 피치에 따라 전류와 추력이 달라진다.
제조사 표가 단일 모터의 신품 배터리 조건만 제공한다면 최종 판정 자료가 아니다.

보유품 판정:

- 8–9인치/6S 조합에서 모터당 25 N 근처의 데이터가 있고 최대전류가 허용 범위이면 **벤치 후보**.
- 필요한 추력이 10인치 이상에서만 나오면 기체 상한 질량과 짐벌 관성을 다시 검토.
- 데이터가 없거나 프로펠러 조건이 다르면 **상태 불명**으로 두고 회전 시험 전에는 비행 후보로 확정하지 않음.
- 두 모터의 회전 방향은 ESC에서 반대로 설정하고 CW/CCW 프로펠러를 정확히 대응시킨다.

프롭은 동일 제조사·형상·피치의 짝을 사용하고, 균열·변형·허브 손상이 있는 것은 폐기한다.
동축 간격은 고정값을 최적이라고 가정하지 말고 약 \(0.15D\)–\(0.35D\) 범위에서 조절 가능한 시험 구조로 만든다.
여기서 \(D\)는 프로펠러 직경이다.

## 3. ESC 사양

ESC는 4-in-1보다 냉각과 교체가 쉬운 **독립 ESC 2개**를 우선한다.

| 항목 | 기준 사양 v0 |
|---|---|
| 입력 전압 | 6S 정식 지원, 완충 전압 25.2 V 포함 |
| 연속전류 | 선택한 모터·프롭의 실측 최대전류의 1.25배 이상 |
| 단기 피크 | 실측 최대전류의 1.5배 이상 또는 제조사 허용 범위 확인 |
| 시작 후보 | 실측 전류가 아직 없다면 60–80 A급 독립 ESC 2개 |
| 명령 | DShot300 이상, 가능하면 DShot600/BDShot |
| 텔레메트리 | eRPM 필수 권장, 전압·전류·온도 텔레메트리 권장 |
| 펌웨어 | PX4에서 사용할 프로토콜과 텔레메트리가 검증된 버전 |
| 냉각 | 동축 기류와 프레임 내부 온도를 고려해 실제 장착 상태에서 검증 |

PX4의 DShot은 체크섬, ESC 보정 불필요, 텔레메트리 등의 장점이 있고, 지원되는 H7 계열 출력에서는 BDShot eRPM을 사용할 수 있다.
[PX4 DShot 공식 문서](https://docs.px4.io/main/en/peripherals/dshot)

정격 숫자만 믿지 않고, 보호 지그에서 전류·전압 강하·ESC 온도를 함께 기록한다.
ESC 정격을 키우는 것으로 커넥터·배선·전원분배 용량 문제가 해결되지는 않는다.

## 4. 배터리와 전원 계통

### 추진 배터리 시작점

| 항목 | 기준 사양 v0 |
|---|---|
| 전압 | 6S LiPo |
| 용량 후보 | 4,000–5,000 mAh |
| 방전 성능 | 두 모터의 합산 실측 전류에서 전압 강하와 온도가 허용되는 셀 |
| 모니터링 | 전체 전압, 전류, 사용량, 가능하면 셀 전압 |
| 주 전력 경로 | 배터리 → 전원분배/전류센서 → ESC 2개 |

예상 체공시간은 실측 평균전류를 얻은 뒤 다음으로 계산한다.

\[
t_{\mathrm{usable}}[\mathrm{min}]
=\frac{60\times0.8\times C[\mathrm{Ah}]}{I_{\mathrm{avg}}[\mathrm{A}]}
\]

0.8은 초기의 사용 가능 용량 가정이며 배터리 제조사·운용 전압·상태에 맞춰 조정한다.

### 전원을 세 계통으로 분리

1. **모터 계통:** 6S를 ESC에 직접 공급.
2. **서보 계통:** 별도 HV BEC. 기준 7.4–8.4 V, 연속 15 A 이상, 순간 25–30 A급 후보.
3. **비행제어기·컴퓨터 계통:** 비행제어기용 검증된 이중 전원 모듈과 Jetson용 전용 DC-DC.

Jetson Orin Nano 개발키트의 기본 전력 모드는 현재 공식 가이드에서 보통 25 W로 설명되고, 개발키트는 19 V 어댑터와 DC 잭을 사용한다.
공식 캐리어 보드 사양의 DC 입력 능력은 19 V, 4.2 A로 제시된다.
[NVIDIA 전원 모드](https://docs.nvidia.com/jetson/orin-nano-devkit/user-guide/latest/howto.html),
[개발키트 캐리어 보드 사양](https://developer.nvidia.com/downloads/assets/embedded/secure/jetson/orin_nano/docs/jetson_orin_nano_devkit_carrier_board_specification_sp.pdf)

따라서 6S 완충 전압 25.2 V를 개발키트 DC 잭에 직접 넣지 않는다.
개발키트 탑재 시에는 **입력 범위가 6S 완충 전압을 포함하고, 출력 19 V·최소 4.2 A를 보장하는 저리플 DC-DC**를 시작 후보로 둔다.
카메라·SSD·USB 장치 부하와 순간 응답을 포함하여 벤치에서 먼저 검증한다.
초기 TVC 벤치와 첫 자세 안정화 시험에서는 Jetson을 기체 밖에 두고 제공 어댑터로 전원 공급한다.

서보, Jetson, 비행제어기에 하나의 저가 BEC를 공유하지 않는다. 각 전원 계통은 공통 기준 전위와 노이즈 경로를 의도적으로 설계하고,
배선 정격·역극성·과전류·서지 보호는 선택한 부품 제조사의 회로 지침에 맞춘다.

## 5. TVC 짐벌과 서보

원본 MG90S급은 새 1.8 kg 상한 기체의 최종 구동기로 확정하지 않는다. 다음을 시작 사양으로 둔다.

| 항목 | 기준 사양 v0 |
|---|---|
| 축 | 직교 2축, 실제 추력축을 회전 |
| 서보 | HV 디지털 금속기어 또는 BLDC 서보 2개 |
| 정격 토크 후보 | 정격 전압에서 25 kgf·cm 이상/축 |
| 속도 후보 | 무부하 사양 0.10 s/60° 이하. 실제 부하 응답은 별도 계측 |
| 입력 갱신 | 200 Hz 이상 지원 권장. 제어 주기와 실제 내부 갱신을 구분 |
| 출력각 | 기계 동작 ±15° 이상, 하드 스톱은 약 ±20°, 초기 명령 제한 ±8° |
| 감속 | 2:1–3:1 범위 후보. 토크·속도·유격의 교환관계를 실측 |
| 위치 측정 | 짐벌 출력축 엔코더 우선. 최소 12 bit, 반복 정밀도 0.2° 목표 |
| 유격 목표 | 출력축 왕복 히스테리시스 0.5° 이하를 목표로 측정 |

25 kgf·cm는 최종 설계 계산값이 아니라 첫 후보를 거르는 기준이다.
추력축이 회전 중심을 지나면 정적 추력 자체가 서보를 크게 비트는 구조를 피할 수 있지만,
모터·프롭의 자이로 효과, 케이블 힘, 질량 불균형, 축 오차, 진동 하중은 남는다.
최종 토크는 실제 조립체의 스텝 응답과 온도로 결정한다.

짐벌은 다음을 조절할 수 있게 설계한다.

- 두 로터 축 정렬.
- 상·하 로터 간격.
- 질량중심에서 TVC 유효 작용점까지 거리.
- 엔코더 영점과 서보 링크 길이.
- 케이블이 짐벌 토크에 미치는 영향.

출력 외피가 주요 추력 하중을 전달하도록 만들지 않는다. 모터 마운트, 짐벌 베어링 블록과 카본 골격을 주 하중 경로로 두고,
로켓 형상의 출력 쉘은 보호·공력·정비 패널 역할로 분리한다. 원본 짐벌과 프레임은 새 모터와 질량에 비례 확대하지 않고 새로 설계한다.

## 6. 비행제어기와 Jetson의 역할

### 실시간 비행제어기

PX4 기준선에는 **Pixhawk 6X/FMUv6X급**을 권장한다. FMUv6X는 STM32H753, 3개 IMU, 2개 기압계, 8개 FMU PWM, 2개 CAN을 제공하며 PX4의 표준 지원 대상이다.
[PX4 Pixhawk 계열 비교](https://docs.px4.io/main/en/flight_controller/pixhawk_series)

필요 기능:

- H7급 MCU와 충분한 로깅 성능.
- 모터 2개용 DShot/BDShot 출력.
- TVC 서보 2축 출력 또는 별도 스마트 액추에이터 버스.
- 전원 이중화 또는 독립적인 안정 전원.
- Jetson과 연결할 TELEM/UART, CAN 또는 Ethernet.
- 안전 스위치, RC 수동 개입, 독립적인 KILL 경로.

표준 쿼드로터 airframe 설정을 그대로 사용하지 않는다. 이 기체는 모터 2개와 TVC 2축의 맞춤 제어 할당과 airframe 정의가 필요하다.

### Jetson Orin Nano

Jetson이 담당할 것:

- 카메라 드라이버와 하드웨어 타임스탬프 확인.
- VIO, AprilTag, 장애물/착륙 지점 인식.
- ROS 2 노드, rosbag/영상 로그.
- 저속 위치·경로·착륙 목표 생성.

Jetson이 처음부터 담당하지 않을 것:

- 모터 정지에 필요한 유일한 KILL 경로.
- 200–500 Hz 자세 내부 루프.
- 통신이 끊기면 유지할 수 없는 유일한 안정화 제어기.

PX4는 companion computer의 ROS 2 통합을 지원하지만, Offboard 링크 손실 시 별도 failsafe 동작을 설정해야 한다.
[PX4 ROS 2](https://docs.px4.io/main/en/ros2/), [Offboard 손실 안전설정](https://docs.px4.io/main/en/config/safety)

## 7. 카메라와 항법 센서

보유 카메라는 다음 기준으로 판정한다.

| 용도 | 기준 사양 v0 |
|---|---|
| VIO 카메라 | 글로벌 셔터 우선, 최소 640×480 60 fps, 넓은 시야각, 고정 노출 지원 |
| 시간 | 프레임 하드웨어 타임스탬프, IMU와 1 ms 수준 동기화 목표 |
| 카메라 IMU | 200 Hz 이상 후보, 원시 타임스탬프와 보정 데이터 접근 가능 |
| 인터페이스 | JetPack에서 검증된 CSI/USB3/GMSL. ROS 2 드라이버 존재 여부 확인 |
| 저장 | NVMe SSD 256 GB 이상 후보, 영상·rosbag 동시 기록 속도 검증 |
| 하향 거리 | 0.1–10 m 이상 후보, 50 Hz 이상, 사용할 바닥·조명에서 검증 |
| 독립 기준 | 모션캡처 또는 외부 카메라+AprilTag. VIO와 같은 센서를 정답으로 사용하지 않음 |

비행제어기의 IMU는 자세 내부 루프에 사용하고, 카메라 IMU는 VIO에 사용한다.
두 센서의 좌표와 시간 오프셋을 보정한 뒤에만 융합한다.

## 8. 계측·안전 장비

준비할 장비:

- 0.1 g 분해능 이상의 전자저울과 캘리퍼.
- 50 N 이상 로드셀. 설계 목표가 37 N이므로 여유를 두어 100 N급 후보 권장.
- 로드셀 증폭기/DAQ, 별도 전압·전류 측정, 광학 또는 ESC RPM 측정.
- 6S·150 A 이상 후보의 전원분배/전류센서. 최종 정격은 실제 최대전류와 배선으로 확정.
- 출력축 엔코더 2개 또는 각도 추적용 고속 카메라와 명확한 마커.
- 오실로스코프 또는 로직 분석기, 멀티미터, 온도 측정 수단.
- 튼튼하게 고정되는 추력 지그, 프로펠러 비산을 고려한 보호 구조, 시험자와 충분한 이격.
- 손을 떼어도 정지 상태로 유지되는 원격 비상정지와 독립적인 모터 신호 차단.
- 배터리 제조사의 충전·보관·손상 대응 지침을 따를 수 있는 비가연성 시험 공간.

로드셀 용량이 크기만 하면 좋은 것은 아니다. 목표 추력 범위에서 충분한 분해능과 샘플링 속도가 있어야 한다.
회전 시험 전에는 지그 고정, 구조 하중, 프로펠러 파손 경로, 원격 차단을 별도로 검토한다.

## 9. 지금 바로 해야 할 다음 단계

### A. 장비 적합성 표 만들기

보유 장비를 다음 형식으로 보내거나 기록한다.

```text
Jetson: 정확한 모델 / 개발키트 또는 모듈+캐리어 / 저장장치 / 실측 질량
카메라: 모델 / 인터페이스 / 최대 FPS / 글로벌·롤링 셔터 / IMU 포함 여부 / 실측 질량
비행제어기: 모델 / PX4 버전 / 사용 가능한 출력과 포트
모터: 모델 2개 / KV / 정격 6S 여부 / 실측 질량 / 제조사 추력표 링크
프로펠러: 직경×피치 / CW·CCW / 재질 / 제조사
ESC: 모델 2개 / 6S / 연속·피크 전류 / DShot·텔레메트리 / 실측 질량
서보: 모델 2개 / 정격 전압 / 토크 / 속도 / 피드백 여부 / 실측 질량
배터리: 6S 여부 / 용량 / 질량 / 상태 / 커넥터
DC-DC/BEC: 입력 범위 / 출력 전압·연속·피크 전류
센서: 거리·flow·GNSS·외부 기준계 모델
계측: 저울 / 로드셀 / 전류센서 / 오실로스코프 / 로직분석기 / 엔코더
```

모델명과 실제 질량이 우선이다. 맞지 않는 장비는 바로 버리지 않고 무회전 벤치·시뮬레이션·보조 계측에 재사용할 수 있는지 구분한다.

### B. Jetson·카메라를 기체 밖에서 먼저 검증

1. 제공 전원으로 Jetson을 부팅한다.
2. 전력 모드, JetPack 버전, 저장장치 여유를 기록한다.
3. 카메라 스트림과 IMU 원시 데이터를 동시에 기록한다.
4. 프레임 FPS, 누락, 타임스탬프 단조 증가, CPU/GPU 부하와 온도를 기록한다.
5. 손으로 움직이는 카메라 리그에서 VIO 공개 예제 또는 기록 재생을 확인한다.

이 단계에는 모터와 프로펠러가 필요 없다.

### B와 병행 — 부품 실측과 CAD-0

1. 모터, 프로펠러, ESC, 서보, 배터리, Jetson, 카메라, 비행제어기의 정확한 모델과 질량을 기록한다.
2. 캘리퍼로 외형, 장착홀, 축, 커넥터와 케이블 출구를 측정한다.
3. 프린터 빌드 볼륨, 노즐과 사용할 재료를 기록한다.
4. 부품 엔벌로프와 카본 골격부터 배치하고, 완성 외피는 CAD-3 이후 출력한다.

상세 입력표와 제작 게이트는 [CAD 재설계 계획](CAD-재설계-계획.md)을 따른다.

### C. 프로펠러 없는 TVC 벤치 제작

1. 모터 대신 같은 질량의 더미 또는 모터만 장착하고 프로펠러는 제거한다.
2. 짐벌 출력축에 각도 엔코더 또는 추적 마커를 설치한다.
3. 비행제어기, 서보 전원, KILL, 명령 타임아웃을 연결한다.
4. ±1°, ±3°, ±5°, ±8°의 계단 명령을 양방향으로 반복한다.
5. 명령각·실제각·전압·시간·포화 여부를 하나의 로그에 남긴다.
6. 축 부호, 영점, 속도, 지연, 오버슈트, 히스테리시스를 계산한다.

이 벤치가 통과하면 `my_airframe.json`의 서보 관련 값을 `measured` 또는 근거가 분명한 `assumed`로 채운다.

## 10. 전체 개발 과정

| 단계 | 작업 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 0. 보유품 판정 | 정확한 모델·질량·데이터시트와 기준 사양 비교 | 목표 질량표와 전원 구조 초안 완성 |
| 0.5. CAD 기준선 | 부품 실측, 골격·짐벌·트레이·분할 외피 재설계 | 간섭 없는 전체 조립과 질량중심 조절 범위 확인 |
| 1. Jetson/카메라 독립 검증 | 영상·IMU·타임스탬프·온도·저장 성능 확인 | 30분 이상 로그에서 누락과 시간 문제 설명 가능 |
| 2. 무회전 TVC 벤치 | 짐벌 축·영점·지연·속도·유격·KILL 검증 | 반복 가능한 실제각 로그 확보 |
| 3. 추진계 시험대 | 단일 로터와 동축의 추력·전류·RPM·온도·토크 측정 | 저전압에서 37 N 목표 평가, 동축 손실 식별 |
| 4. 파라미터 확정 | 질량·CoM·관성·레버암·구동기·추력 계수 기록 | 별도 검증 데이터에서 모델 오차 수치화 |
| 5. Gazebo/SIL | 맞춤 TVC 플러그인·센서 지연·고장·제약 구현 | 기준 LQI가 목표 초기조건에서 반복 안정화 |
| 6. 제어 연구 | LQI → 지연 확장 LQI → 제약 MPC/INDI 비교 | 같은 입력·외란 조건에서 지표와 실패 사례 확보 |
| 7. HIL | 실제 FC·ESC 신호·서보·통신·Jetson 연결 | 최악 실행시간, 포화, 링크 손실, 센서 오류 안전 동작 |
| 8. 제한 실기 | 보호된 구속 시험 후 작은 자세·추력 범위 | 수동 KILL과 자동 timeout, 모델 예측과 로그 확인 |
| 9. 초기 자유비행 | Jetson 없이 FC 단독 자세·고도 안정화 | 안전구역에서 반복 이륙·호버·착륙, 이상 종료 가능 |
| 10. VIO 통합 | Jetson 위치 추정은 보조 입력으로 추가 | 외부 기준 대비 지연·오차·드롭아웃 평가 |
| 11. 확장 연구 | GPS 없는 위치 유지, 정밀 착륙, MPC/강인제어 | 기준선과 동일 조건의 정량 비교 및 재현 가능한 데이터 |

구속 시험의 줄과 지그는 기체에 힘을 추가하므로 자유비행 모델과 같은 데이터로 취급하지 않는다.
Jetson과 카메라는 1단계에서 먼저 연구할 수 있지만, 기체 탑재는 9단계 기준선을 확보한 뒤 진행한다.

## 11. 바꾸어야 하는 조건

다음 중 하나가 발생하면 기준 사양 v0를 수정한다.

- 실제 완성 질량이 1.8 kg를 넘음.
- 동축 저전압 실측 총추력이 36.6 N 미만.
- 호버 추력에서 모터·ESC·배터리·배선 온도 또는 전압 강하가 허용되지 않음.
- 짐벌 출력축 지연·유격이 목표 제어 대역폭을 만족하지 못함.
- Jetson DC-DC가 카메라·SSD 부하에서 재부팅하거나 비행제어기 센서에 간섭을 만듦.
- 카메라 시간 동기화 또는 드라이버가 선택한 JetPack/ROS 2 환경에서 재현되지 않음.
- 맞춤 제어 할당과 failsafe를 현재 비행제어기에서 안전하게 구현할 수 없음.

수정은 실패가 아니라 이 과정의 정상적인 설계 반복이다. 단, 실측에서 부족한 추진계나 전원 문제를 제어 게인으로 보상하려고 하지는 않는다.
