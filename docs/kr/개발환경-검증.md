## 그대로 사용하면 안 되는 부분

- STM32 경고 중 `LAND_DESCENT_RATE_MPS`는 `global.h` 0.3과 `freertos.c` 0.4로 중복 정의,
  `LAND_ALT_THRESHOLD_M`은 각각 0.06과 0.10이다. 단일 설정으로 통일하기 전에 실제 상태 전이를 검토한다.
- 원본 GCS `main.py`는 macOS 시리얼 포트 문자열을 하드코딩한다. Windows/Ubuntu에서는 포트 선택 기능이 필요하다.
- `cal.py`는 socat와 `/tmp` 가상 포트 및 별도 수정 MotionCal을 전제로 한다. Windows에서 그대로 동작한다고 확인되지 않았다.
- `apps/python/sim.py`의 pygame/OpenGL 시뮬레이터는 이번 설치/검증 대상이 아니다. LQI 계산과 운동 모델도 다르다.
- 위 검사 스크립트의 통과/타임아웃을 따로 확인해야 한다. 여러 명령을 한 줄로 실행하면 마지막 명령의
  종료 코드가 앞선 실패를 가릴 수 있다.

## Ubuntu로 진행할 때

권장: Ubuntu 24.04 LTS + ROS 2 Jazzy + Gazebo Harmonic.
[PX4 공식 환경 안내](https://docs.px4.io/main/en/ros2/user_guide)와
[Gazebo 조합 안내](https://gazebosim.org/docs/jetty/ros_installation/)에 근거한다.

1. 별도 PC/SSD의 네이티브 설치 또는 WSL2 중 사용할 방식을 정한다. USB 실기 연구는 네이티브 우선.
2. 기존 데이터 백업 및 설치 디스크를 확인한 후 OS 설치를 별도로 진행한다. 현재 디스크 파티션은 건드리지 않았다.
3. `research/README.md`의 Python 가상환경 명령으로 분석 기준선부터 재실행한다.
4. 공식 ROS 2 Jazzy 설치 안내를 따라 저장소/패키지를 준비하고 Gazebo 호환 조합을 설치한다.
5. ROS talker/listener와 기본 Gazebo world를 먼저 확인한다. 이후 TVC 전용 기체 모델을 만든다.
6. PX4를 선택할 때에는 해당 릴리스와 `px4_msgs` 버전을 맞추고 커밋을 고정한다.
   원본 custom STM32 펌웨어와 PX4는 서로 대체 가능한 같은 프로젝트가 아니다.

현재 PC의 16 GB RAM에서는 처음부터 여러 대의 고해상도 카메라 시뮬레이션/학습을 동시에 돌리기보다,
단일 기체·낮은 카메라 해상도로 실시간 배율과 메모리를 측정하며 시작하는 것을 권한다.
이는 하드웨어 구성에 따른 실용적 제안이며 Gazebo 성능을 실제 측정한 결과는 아니다.

추가 파일은 로컬 `bench-test`에 있고 아직 커밋/푸시하지 않았다. 원본 비행 소스와 원본 보정값은 변경하지 않았다.
