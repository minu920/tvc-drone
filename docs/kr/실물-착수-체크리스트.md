# 4단계 — 실물 프로젝트 착수 체크리스트

작성: 2026-09-16. 이 문서는 원본 기체의 조립 순서를 복사하는 설명서가 아니라, 새 연구 기체를 안전하고 측정 가능하게 시작하기 위한 순서다.

## 이번 단계의 결정

추진계·전원·서보·센서의 시작 범위는 [연구기체 기준 사양 v0](하드웨어-기준사양.md)를 사용한다.

첫 실물 목표는 **자유비행 기체가 아니라 프로펠러를 제거한 2축 TVC 벤치**다.

이 벤치에서 먼저 확인할 것은 다음 다섯 가지다.

1. 명령한 축과 실제 짐벌 축의 방향이 일치하는가.
2. 명령각과 실제 출력각의 관계가 반복 가능한가.
3. 유격·히스테리시스·속도·지연이 어느 정도인가.
4. 전원 변동이나 통신 중단 시 짐벌과 제어기가 안전한 상태로 가는가.
5. 명령, 실제 각도, 전압, 시간 정보를 같은 로그에 남길 수 있는가.

프로펠러 회전, 추력 시험, 줄에 매단 시험, 자유비행은 이 벤치가 통과한 뒤의 별도 단계다.

## 오늘 해야 할 일

### 1. 예산 상한 결정

아직 제품을 고르지 말고 아래 세 항목에 사용할 상한을 원화로 정한다.

| 항목 | 예산 상한 | 포함할 것 |
|---|---:|---|
| 기체·추진·전장 | 미정 | 프레임, 모터 2개, 프로펠러, ESC, 배터리, 제어기, 서보, 배선 |
| 계측·안전 | 미정 | 전자저울, 각도 측정, 전류·전압 측정, 로드셀/추력 지그, 보호 구조, 원격 차단 |
| 비전·보조 컴퓨터 | 미정 | 카메라, 거리센서, 동기화 장치, 온보드 컴퓨터. 1차 벤치에서는 구매 보류 가능 |

총액만 정하면 안전·계측 비용이 밀릴 수 있으므로 세 항목을 분리한다. 고가 카메라보다 먼저 실제 구동각과 추력을 측정할 수 있어야 한다.

### 2. 보유품 전수 조사

상자와 책상에 있는 부품을 먼저 모으고, 부품마다 라벨이 보이게 사진을 찍는다. 모델명을 모르면 사진만 남기고 추측하지 않는다.

| 분류 | 기록할 내용 |
|---|---|
| 모터·프로펠러 | 정확한 모델, 수량, CW/CCW 구성, 손상 여부, 데이터시트/구매 링크 |
| ESC | 모델, 수량, 정격, 입력 전압 범위, 펌웨어/프로토콜 |
| 서보·짐벌 | 모델, 수량, 정격 전압, 기어·링크 부품, 위치 피드백 가능 여부 |
| 비행 제어기 | 보드명, MCU, 센서, 사용 가능한 PWM/DShot/UART/CAN/SPI/I2C, 디버거 |
| 전원 | 배터리 셀 수·용량·상태, 충전기, BEC/DC-DC, 전원 센서, 커넥터 |
| 센서 | IMU, 기압계, ToF/LiDAR, optical flow, 카메라, GNSS의 정확한 모델 |
| 제작 장비 | 3D 프린터, 납땜 장비, 캘리퍼, 저울, 멀티미터, 오실로스코프/로직 분석기 |
| 시험 공간 | 실내 크기, 고정 가능한 튼튼한 작업대, 환기, 주변 사람과 가연물 통제 여부 |
| 컴퓨터 | Ubuntu를 설치할 PC, GPU, RAM, 저장공간, 사용할 USB·네트워크 포트 |

각 부품은 `보유 / 주문 필요 / 상태 불명 / 사용 제외` 중 하나로 표시한다.

### 3. 작업 공간을 두 구역으로 나누기

- **무회전 구역:** 프로펠러를 장착하지 않고 센서·서보·통신·로깅만 시험한다.
- **회전 시험 구역:** 추후 별도의 보호 지그, 비산 방지, 충분한 이격, 원격 KILL을 마련한 뒤 사용한다.

현재는 무회전 구역만 준비한다. 배터리 충전·보관·손상 판단은 사용하는 배터리와 충전기 제조사의 안전 지침을 따른다.
손상되었거나 상태가 불명확한 배터리를 시험 전원으로 사용하지 않는다.

### 4. 시작 상태 사진과 파일 남기기

다음 사진을 촬영한다.

- 전체 보유 부품 한 장.
- 모델 라벨이 읽히는 근접 사진.
- 사용할 작업대와 주변 공간.
- 이미 조립된 기체가 있다면 정면·측면·상면.

개인정보, 집 주소, 시리얼 번호처럼 공개할 필요가 없는 내용은 가린다. 사진 이름은 날짜와 내용을 포함한다.
예: `2026-09-16_motor-label-01.jpg`.

## 정보를 받은 뒤 결정할 것

위 정보가 들어오면 다음 순서로 확정한다.

1. **기체 목표 질량 범위와 구조:** 센서·컴퓨터를 포함한 구성 후보를 2개 이내로 줄인다.
2. **추진계 요구조건:** 총중량과 짐벌 최대각에서 필요한 수직 추력을 계산한다.

   \[
   T_{\mathrm{vertical}}=T_{\mathrm{total}}\cos\theta_{\mathrm{TVC}}
   \]

   정적 추력/무게 비율만으로 비행 안전성을 판정하지 않으며, 동축 간섭과 배터리 전압 저하를 실측 대상으로 남긴다.
3. **비행 제어기 경로:** 원본 STM32를 학습 기준선으로 유지할지, PX4 지원 보드를 별도 기준선으로 둘지 정한다.
4. **서보·짐벌 계측법:** 외부 각도 피드백, 카메라 추적 또는 엔코더 중 보유 장비에 맞는 방법을 고른다.
5. **1차 구매표:** 보유품과 중복되지 않도록 후보·수량·가격·구매 이유·대체품을 정리한다. 이때 최신 가격과 Linux/ROS 지원을 다시 확인한다.
6. **Ubuntu 환경:** 기본안은 Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic이다. 저장장치와 설치 방식이 정해진 뒤 설치한다.

## 단계별 통과 조건

| 단계 | 실물 작업 | 통과 조건 |
|---|---|---|
| 0. 착수 조사 | 예산·보유품·공간 기록 | 모델명과 미정 항목이 구분되고 중복 구매를 피할 수 있음 |
| 1. 무회전 TVC 벤치 | 제어기·전원·서보·짐벌·로깅 구성 | 프로펠러 없음, 축 부호 확인, KILL/타임아웃 확인, 반복 가능한 각도 로그 |
| 2. 구동기 식별 | 각도 명령 계단 입력과 실제 각도 기록 | 지연·시정수·속도·유격을 반복 측정하고 조건/오차를 기록 |
| 3. 보호된 추진계 벤치 | 동축 추력·전류·전압·반작용 토크 측정 | 보호 구조와 원격 차단이 검토되고, 전압별 반복 데이터 확보 |
| 4. 모델 검증 | 식별에 쓰지 않은 데이터로 예측 비교 | 오차를 수치화하고 맞지 않는 모델 항을 구분 |
| 5. SIL/HIL·구속 시험 | 센서 오류·명령 만료·포화·계산 지연 시험 | 실패 시 안전 상태 전환과 로그 보존 확인 |
| 6. 제한 자유비행 | 안전한 시험 계획에 따른 점진적 확대 | 이전 단계 통과, 비행 전 체크리스트, 독립적인 종료 수단 확보 |

단계를 건너뛰지 않는다. 특히 원본 펌웨어가 빌드된다는 사실과 실물 비행 준비가 되었다는 판단은 별개다.

## 지금은 하지 않을 것

- 제품 목록을 보지 않고 모터·배터리·서보를 먼저 주문하지 않는다.
- 원본 질량·관성·게인·서보 오프셋을 내 기체 값으로 복사하지 않는다.
- 프로펠러를 장착한 상태에서 최초 전원 인가나 서보 방향 확인을 하지 않는다.
- 카메라·AI 컴퓨터를 먼저 탑재해 목표 질량을 불명확하게 만들지 않는다.
- 자유비행으로 제어기와 센서 부호를 동시에 디버깅하지 않는다.

## 첫 번째 마일스톤

첫 마일스톤은 다음 한 문장으로 정의한다.

> 프로펠러가 없는 2축 TVC 벤치에서 시간 동기화된 명령각·실제각·전압 로그를 기록하고, 축 부호·KILL·명령 타임아웃을 재현 가능하게 검증한다.

이 마일스톤이 끝나면 `my_airframe.json`에서 질량·레버암·Ixx 및 구동기 관련 항목을 실제 구성에 맞게 채우고, 그 다음 보호된 추력 시험 설계를 시작한다.
