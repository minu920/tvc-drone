# 3단계 B — 파라미터 한 곳에서 관리하기

2026-09-16. 이 단계는 계산 입력과 출처를 정리하는 작업이다. 부품 구매·OS 설치·실기 보정·비행 펌웨어 변경은 포함하지 않는다.

## 지금 사용할 두 파일

| 파일 | 용도 | 현재 상태 |
|---|---|---|
| `research/parameters/upstream_reference.json` | 원본 연구 계산 재현 | 기존 값을 그대로 보존. 본인 기체의 실측값이 아님 |
| `research/parameters/my_airframe.json` | 앞으로 만들 기체의 설계·계측값 | 중력 관례값만 입력. 나머지 13개 항목은 미정 |

두 파일 사이에는 자동 상속이나 누락값 대체가 없다. 내 기체 질량이 비어 있으면 원본의 질량을 사용하지 않고, 그 계산을 중단한다.
원본 값을 이용한 예제를 실행하려면 원본 프로파일을 선택한다. 아직 정하지 않은 내 기체 값을 예제 실행 목적으로 채우지 않는다.

## 값 하나를 기록하는 규칙

각 항목에는 `value`, `unit`, `status`, `source`가 있다.

| 상태 | 뜻 | 입력 규칙 |
|---|---|---|
| `unknown` | 아직 정하지 않았거나 모름 | 값은 반드시 `null`. 출처에는 필요한 설계 결정 또는 측정 계획 기록 |
| `upstream_reference` | 원본 프로젝트의 참고값 | 내 기체의 실측값과 구분 |
| `convention` | 명시적으로 선택한 관례값 | 예: 초기 연구에서 사용하는 중력 가속도 |
| `assumed` | 시뮬레이션용 가정 또는 실험 설계값 | 선택 근거와 적용 범위 기록 |
| `cad` | CAD에서 계산한 값 | CAD 버전, 기준점·축, 재료와 질량 조건 기록 |
| `measured` | 실험으로 측정한 값 | 로그/기록 위치, 날짜, 조립 상태, 전압 등 조건 기록 |

`measured`라는 표시는 사용자가 입력한 출처 분류일 뿐 자동으로 측정의 정확성을 보증하지 않는다.
가능하면 `source`에 측정 기록을 연결하고 그 기록에 반복 측정, 오차, 배터리·탑재물 구성을 남긴다.

단위 문자열은 변환 명령이 아니다. 예를 들어 각도는 rad, 길이는 m, 질량은 kg, 추력은 N으로 먼저 변환해 넣는다.
검사기는 허용하지 않는 단위 표기를 거부하지만, 숫자를 잘못 환산하고 올바른 단위 표기를 붙인 모든 실수까지 알아낼 수는 없다.

## 어떤 항목부터 채우는가

1. **기체 구성 결정:** 예산, 보유 부품, 크기, 배터리, 탑재 센서 후보를 정한다. 구매 전에는 설계 추정값만 `assumed`로 기록한다.
2. **기하·질량:** 완성 조립 상태의 질량, 질량중심, 질량중심에서 짐벌 유효 작용점까지 거리, CAD 관성을 정리한다.
3. **구동기:** 실제 짐벌의 각도 범위·속도·응답 시간을 확인한다. 서보 축 각도와 짐벌 출력 각도를 구분한다.
4. **추진계:** 보호 지그·차폐·원격 차단을 준비한 후 동축 조립체의 추력과 반작용 토크를 계측한다.

프로펠러 제거 상태에서 할 수 있는 축·신호·간섭 확인부터 진행한다. 추진계 시험 방법과 안전 조건은 별도 단계에서 정한다.
기체를 바꿔도 레버암 방향이 질량중심 아래라는 현재 모델의 가정을 유지할 수 있는지 확인해야 한다.
현재 관성 입력은 기체 축을 주축으로 보는 대각 근사다. CAD의 관성곱이 무시하기 어렵다면 값을 억지로 맞추지 말고 모델을 확장한다.

모든 미정 항목을 채워야 모든 도구를 실행할 수 있는 구조는 아니다.

| 점검 이름 | 필요한 항목 | 의미 |
|---|---|---|
| `translation` | 질량, 중력 | 병진 가속도 계산 입력 |
| `roll_study` | 질량, 중력, 레버암, Ixx, 짐벌 각도·속도 한계, 설계 시정수, 실험 주기 | 기존 1축 오프라인 비교 실험 입력 |
| `diagonal_inertia` | Ixx, Iyy, Izz | 대각 관성행렬 구성 입력 |
| `thrust_margin` | 질량, 중력, 최대 총추력 | 정적 추력/무게 비율 계산 입력. 비행 가능 판정이 아님 |
| `reference_lqi` | 원본용 계수·비용·프로파일 | 원본과의 수학적 등가성 비교 전용 |

`yaw_accel_per_legacy_mass_equivalent`는 원본 비교 전용이다. 내 기체 프로파일에서는 미정으로 두어도 1축 실험에 지장이 없다.
내 기체의 다축 제어기를 만들 때 원본 yaw 계수나 LQI 비용을 자동으로 복사하지 않는다.
샘플 주기나 설계 시정수처럼 설계 선택이 필요한 항목은 무조건 실측값으로 분류하지 않는다.

## 실행 방법

저장소 루트에서 실행한다. Windows:

```powershell
.\.venv\Scripts\python.exe research/parameter_check.py --profile research/parameters/my_airframe.json
.\.venv\Scripts\python.exe research/parameter_check.py --profile research/parameters/my_airframe.json --require roll_study
.\.venv\Scripts\python.exe research/parameter_check.py --profile research/parameters/upstream_reference.json --output artifacts/parameter-review/upstream
.\.venv\Scripts\python.exe research/actuator_study.py --profile research/parameters/upstream_reference.json --output artifacts/actuator-study/reference-run
```

Ubuntu에서는 실행 파일만 `.venv/bin/python`으로 바꾼다. 파라미터 점검 자체는 표준 라이브러리만 사용하므로 일반 `python3`로도 실행할 수 있다.
Ubuntu에서의 실제 실행은 아직 검증하지 않았다.

- 일반 점검은 미정값이 있어도 형식이 유효하면 종료 코드 0이다.
- `--require`로 지정한 계산의 입력이 부족하면 종료 코드 2와 항목 목록을 반환한다.
- `actuator_study.py`는 선택한 프로파일이 불완전하면 결과 폴더를 만들기 전에 중단한다.
- `model_check.py`는 의도적으로 원본 프로파일만 사용한다. 내 기체 성능 검증용이 아니다.
- `--output`의 같은 이름 결과는 다시 실행하면 갱신된다. 보존할 실험은 새 출력 폴더를 사용한다.

출력의 `summary.json`에는 실행 당시 프로파일 전체와 파일 경로, 원본 파일 바이트의 SHA-256을 저장한다.
이후 프로파일을 수정해도 이전 실험이 어떤 값으로 실행되었는지 확인할 수 있다.
샘플링 주기·기체 물성·구동기 한계는 프로파일에서 읽지만, 외란 시나리오·비교할 시정수 목록·제어 비용은 아직 실험 스크립트의 실험 설계다.

## 검사 범위와 한계

- 필수 항목·출처·상태, 미정값과 상태의 일치, 숫자 유한성, SI 단위 표기, 양수 조건을 검사한다.
- 중복 JSON 키와 알 수 없는 파라미터 이름을 거부한다.
- 현재 정립 호버 모델에 맞지 않는 짐벌 각도 범위와, 세 주관성 값의 삼각부등식 위반을 거부한다.
- 최대추력이 무게를 넘지 않으면 경고한다. 비율이 크다고 안전한 비행이나 충분한 제어 여유를 보증하지 않는다.
- 실제 센서 축, 모터 회전 방향, 서보 연결, 계측 정확도, 제어기 안정성은 이 검사로 검증되지 않는다.
